# A Skill for the Files in a Trademark Pack

## Why Care?

Every surface that shows a brand asks for a specific file. A browser tab asks
for the favicon, an iPhone home screen for a PNG, and Vercel's project list,
crawlers and RSS readers for `/favicon.ico` by that exact path. When a file is
missing, each one shows a default instead: Astro's logo, a globe, or a
stand-in. Auditing the projects on changelog.lossless.group and the
context-v-corpus splash turned up all of these, one at a time.

## What changed

- **The pack, written down:** `favicon.svg`, `favicon.ico` (16, 32, 48 and
  256px), `apple-touch-icon.png` (180px, opaque), `appIcon__<Brand>.svg`,
  `wordmark__<Brand>.svg` and `trademark__<Brand>.svg`, with what each is for
  and where it shows.
- **The head links,** in the order that keeps SVG for browsers that read it.
- **The rules behind the failures we hit:** outline text instead of live
  `<text>`, check renders in Chrome rather than ImageMagick, replace scaffold
  favicons, use the canonical v3 Lossless marks, and leave client marks to
  the client.
- **A sub-brand from a house wordmark:** how The Lossless Toolkit's wordmark
  re-set "Group." in the original's own face.
- **Scripts:** `outline-text.py` turns font text into SVG paths with HarfBuzz
  shaping, and `make-icons.sh` renders the `.ico` and the home-screen PNG from
  the SVGs through headless Chrome.

The astro-knots MCP carries this skill too, synced from here.
