# Artifacts Skill: New Token Format, and the Token That Repo Create Prints

## Why Care?

An agent creating an Artifacts repo was told to keep tokens out of its output, with a redaction filter keyed to the `art_v1_` prefix the skill documented. Cloudflare now issues `art_v2_x_` tokens, so the filter missed one. `wrangler artifacts repos create` printed a write token into the session transcript. It was scoped to one empty repo and was revoked within minutes, but the skill had set the agent up to miss it.

## What's New?

- **The token format is current.** Repo tokens are documented as `art_v2_x_<40 hex>?expires=…`, with `art_v1_` as the older form. The skill now says to match any `art_v<n>_` prefix, because a filter keyed to one prefix misses the next format.
- **Creating a repo prints a write token.** A new rule covers Wrangler's plain-text output and the REST JSON, gives a redaction filter that matches every format, and gives the list-then-revoke steps for getting rid of the token right after creation.
- **The create token is a fact, not a guess.** It was marked *(verify)*. It is a `write` token with a 24-hour TTL, tested 2026-11-17.
- **Wrangler's login is a stopgap for a missing permission.** `wrangler login` requests `artifacts:write`. Its OAuth token also works as a Bearer token on the REST routes, including token listing and revocation, which Wrangler can't do itself. It worked while the account's API token still returned code 10000.
- **Tested-live status updated.** Token revocation moves to tested. Fork, import and delete remain untested.
- **API map:** the token-mint row notes the new `plaintext` prefix.
