# Floorplan Is Vendored as a Skill, on Trial

## Why Care?

[Floorplan](https://github.com/haydenschmitty/floorplan) maps a codebase as an interactive node graph. Every subsystem, module, file and HTTP route gets a plain-language name and a one-line description, and the imports and HTTP calls between them are drawn as edges. It covers one repo or several side by side, and saves the result as a self-contained `floorplan/index.html`. Given a PRD instead of code, it drafts a blueprint: the same map, planned.

It overlaps with Archify. Archify draws a diagram you specify and checks its geometry. Floorplan scans the code and has the agent name what it finds. We're trying both to see which one we keep reaching for.

## What changed

- **Mounted** our fork [`lossless-group/floorplan`](https://github.com/lossless-group/floorplan) as the submodule `floorplan` at `94f81b4` (Floorplan 0.11.0). The submodule has `upstream` set to `haydenschmitty/floorplan`, so we can pull upstream changes into the fork.
- **Excluded from Stow**, because the skill sits two levels down at `floorplan/skills/floorplan/`. Link it by hand:
  `ln -s <mono-root>/context-v/agent-skills/floorplan/skills/floorplan ~/.claude/skills/floorplan`
- **Recorded** in the Skills table, in `THIRD-PARTY.md`, and in the root monorepo README's third-party table.

Upstream ships Floorplan as a Claude Code and Codex plugin. We link only the skill. Its commands use `${CLAUDE_SKILL_DIR}`, so they work from the linked folder without the plugin. It has no dependencies, hooks or MCP servers; its scripts run on plain Node.
