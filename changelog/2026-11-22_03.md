# The First Skill Pack: Astro Knots

## Why Care?

A flat folder of forty-odd skills tells a visitor nothing about which ones are
for them. Someone building an Astro site needs nine of them, scattered
alphabetically among CRM guides, VC memo methods and expense reports. A pack
puts those nine in one place with a README that says who they are for.

## What changed

- **`skill-packs/astro-knots/skills/`** now holds `astro-knots`,
  `theme-system`, `maintain-design-md`, `lossless-flavored-markdown`,
  `maintain-splash-pages`, `generate-consistent-og-images`,
  `open-graph-share-seo-geo`, `openpanel-analytics` and
  `trademark-packs-files`, moved with their history.
- **Names didn't change.** Both sync scripts link each pack skill flat, as
  `~/.claude/skills/<name>`, so harnesses load them exactly as before.
- **This site** finds pack skills and keeps each one's page at
  `/skills/<name>/`.
- **Stow** can't link that deep, so it skips `skill-packs/`; the ignore file
  shows the one-line loop that links them by hand.
- **Outside this repo:** the Astro Knots MCP's sync looks inside packs, and the
  context-v-corpus scripts count pack skills as canonical.

The pack folder has the layout a pack repo would have, so it can split out
into its own repo later without reshuffling.
